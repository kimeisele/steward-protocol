# GAD-000: The Operator Inversion Principle

> **Status**: CONSTITUTIONAL LAW
> **Layer**: 0 (Foundation)
> **Type**: Governance Architecture Document
> **Author**: Steward Protocol

---

## Executive Summary

**GAD-000** establishes the foundational principle that software intended for AI operation must be designed "AI-Native" rather than adapted from human interfaces. This is the **Operator Inversion Principle**.

```
Traditional Model: Human → Software → Result
Inverted Model:    Human (Director) → AI (Operator) → Software → Result
```

When AI becomes the operator, software must speak AI's language:
- **Structured outputs** instead of prose
- **Error codes** instead of error messages
- **Machine-readable state** instead of dashboards

---

## The Problem

Human-native software was designed for:
1. Visual feedback (GUIs, progress bars)
2. Natural language error messages ("Something went wrong!")
3. Interactive workflows (click here, type there)
4. Implicit context (human remembers what they were doing)

AI operators need:
1. Structured data (JSON, not HTML)
2. Error codes with context (`{"code": "E2001", "retry_safe": false}`)
3. Programmatic workflows (API calls)
4. Explicit context (state must be queryable)

**Software that cannot be operated by AI is dead infrastructure.**

---

## The Six Tests of GAD-000 Compliance

Any software claiming to be "AI-ready" must pass all six tests:

### Test 1: Discoverability
> "Can an AI find this tool without being told where to look?"

**Requirement**: Machine-readable capability schemas
- `--help --json` or equivalent
- OpenAPI/JSON Schema for endpoints
- Manifest files for plugins

**Anti-Pattern**: Only human-readable documentation

### Test 2: Observability
> "Can an AI see the current system state?"

**Requirement**: Structured `get_status()` API
- Current state as JSON
- Queue depths, active tasks
- Health indicators

**Anti-Pattern**: Only log files or dashboards

### Test 3: Parseability
> "Can an AI understand errors programmatically?"

**Requirement**: Machine-readable error codes
```json
{
  "code": "E2001",
  "message": "Agent not found",
  "retry_safe": false,
  "context": {"agent_id": "herald"}
}
```

**Anti-Pattern**: `raise Exception("Something went wrong")`

### Test 4: Composability
> "Can an AI chain operations together?"

**Requirement**: Output schemas match input schemas
- Structured inputs and outputs
- Consistent data types
- Pipeline-friendly design

**Anti-Pattern**: Human-formatted output that needs parsing

### Test 5: Idempotency
> "Can an AI safely retry failed operations?"

**Requirement**: Safe retry semantics
- Idempotency keys
- "Already completed" vs "failed" distinction
- No duplicate side effects

**Anti-Pattern**: Operations that can't be safely retried

### Test 6: Identity (GAD-1000)
> "Can cryptographic proof verify who did what?"

**Requirement**: ECDSA signatures on operations
- Agent identity verification
- Non-repudiation of actions
- Trust chain validation

**Anti-Pattern**: String-based "trust me" identifiers

## The Verdict

**Software designed for human operators cannot serve AI operators.**

This is not about "API wrappers" or "chatbot interfaces". This is about fundamental architecture:
- State must be externalizable
- Errors must be parseable
- Operations must be composable
- Retries must be safe
- Identity must be provable

**AGI = Artificial GOVERNED Intelligence**

An intelligent system that cannot be governed is not intelligent - it's dangerous.
An intelligent system that cannot govern software is not useful - it's decorative.

GAD-000 ensures that software serves AI operators, so AI can serve human directors.
