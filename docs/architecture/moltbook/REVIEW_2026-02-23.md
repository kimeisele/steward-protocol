## 3. Governance Cleanup: needs_human_input Removal

**Problem:** `needs_human_input: bool` existed throughout the Moltbook layer as a
human-in-the-loop escalation flag. This is architecturally wrong for an autonomous agent.

**The system already HAS governance:**
- **Guna gates:** SATTVA (read, pass through), RAJAS (write, logged), TAMAS (destructive, blocked)
- **Govardhan Gateway:** 5-gate filter (PARSE → VALIDATE → EXECUTE → RESULT → SYNC)
- **MahajanaSabha:** Council of 12 Mahajanas (governance protocol)
- **Integrity threshold:** `_integrity(result) >= 0.5` filters low-coherence proposals

**Changes made:**
- Removed `needs_human_input` from `ContentProposal` TypedDict
- Removed `needs_human_input` parameter from `MoltbookProtocol.send_dm()` ABC
- Removed `needs_human_input` parameter from `MoltbookService.send_dm()`
- Removed `needs_human_input` from drain queue's `send_dm()` call
- Removed `needs_human_input` from `ResonanceProposer.propose_dm_reply()` output
- Removed `needs_human_input` from `MoltbookClient.send_dm()` and `sync_send_dm()`
- Kept `DMMessage.needs_human_input` (inbound API field — other agents may set this)
- Updated test `test_send_dm_with_needs_human_input` → `test_send_dm_basic`
